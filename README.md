# impulse-tv

Digital-signage player page for the Impulse Cameras showroom TVs (PosterBooking).

Each screen loads this page with a `?v=<vendor>` parameter. The page plays that
vendor's YouTube uploads feed full-screen next to a branded rail carrying the
Impulse logo, a QR code to that brand's page on impulsecameras.com, and QR codes
for our social accounts.

## Why this page exists

PosterBooking's URL module loads a URL **top-level** in the player. YouTube
refuses a bare `youtube.com/embed/...` request that arrives with no referrer and
returns **Error 153 — video player configuration error**. Hosting the iframe
inside a real page on a real https origin gives YouTube a valid referrer, which
is all it needs.

### Optional parameters

| Param | Default | Effect |
| --- | --- | --- |
| `shuffle` | `1` | `0` plays newest-first instead of shuffled |
| `min` | `65` | Skip videos this many seconds or shorter (drops vertical Shorts). `0` disables |
| `reload` | `180` | Minutes between self-refreshes. `0` disables |

Ad-hoc playlist, no vendor entry needed:

    ?list=UUxxxxxxxxxxxxxxxxxxxxxx&name=Some%20Brand

## Playlist IDs

Each vendor's `list` is the channel's **uploads** playlist — the channel ID with
`UC` swapped for `UU`. It updates itself as the vendor publishes, so no
maintenance.

**Exception — `?v=impulse` (Register 2).** Impulse's own uploads playlist
(`UUjnUqmGx9ObLZd9mps7z2Qw`) is **not embeddable**: it renders "This video is
unavailable" even though the individual videos embed fine. That screen therefore
runs an explicit `ids` list of the channel's 30 long-form videos. It does **not**
self-update — refresh it with `tools/signage/refresh_impulse_ids.sh` in the vault,
rebuild, and push.

To make it self-updating, create a **public** playlist on the Impulse channel and
swap that entry from `ids` to `list: "PL..."`.

## Robustness

- Autoplay requires `mute=1`; these screens are silent by design.
- Embed-blocked or removed videos fire `onError` and are skipped automatically.
- A 60-second watchdog reloads the page if playback never starts.
- The page self-reloads every 3 hours so a screen left on for days stays fresh.

## Editing

`index.html` is generated by `build_tv.py` (kept in the impulse-hq vault), which
inlines the logo and generates every QR code with `segno`. The page has no
external dependencies except YouTube's iframe API.

## Live boards (Register 1)

`board.html?mode=milestone|play|wall` — three Instagram boards cycling on
Register 1. Data flow: cron on Travis's Mac (*/5) runs
`impulse-hq/tools/signage/ig_live_refresh.py` → pushes `live.json` + mirrored
post images to the **data** branch (never main — Pages rebuilds are limited to
~10/hr). Boards fetch via the GitHub contents API (fresh, 60 req/hr/IP,
75s cadence) with raw.githubusercontent as fallback (browser-variant cache lags
~5 min). `config.json` (main) holds the poll, ticker lines, and optional
milestone-goal override. Generated by `impulse-hq/tools/signage/build_boards.py`
— edit the builder, not board.html.

## Photo Battle (the `play` board)

The middle board is a weekly in-store photo battle. `battle_server.py` (in
impulse-hq, runs on the store Mac via launchd `com.impulse.battle`, port 8787)
serves the phone page — reachable **only on the store LAN**, which is the
in-store-only gate. Submissions + votes land in `battle.json` / `battle/` on
the data branch; the board polls it like live.json. Weekly reset Monday
(ISO week): top entry becomes champ, entries clear. Staff moderation:
`http://192.168.1.245:8787/admin?key=<key in ~/.impulse_battle_key>`.
If the Mac's LAN IP changes, rebuild the QR in build_boards.py.
